# Платёжный шлюз

Учебный командный проект по дисциплине «Программирование корпоративных систем».
Текущий этап: **практика 1, Java: структура проекта, классы и модификаторы**.

Команда: Охотников Святослав, Сторожев Роман, Паламарчук Даниил.

## Запуск

Нужен JDK 17 или новее. В каталоге проекта выполните:

```sh
make run
```

Команда компилирует исходники в `build/classes` и запускает консольное приложение.
Для отдельной компиляции используйте `make compile`.
Внешних Java-зависимостей на этом этапе нет.

Запуск без `make` в терминале macOS или Linux:

```sh
mkdir -p build/classes
javac --release 17 -encoding UTF-8 -d build/classes $(find src/main/java -name '*.java')
java -cp build/classes ru.university.paymentgateway.Main
```

В IntelliJ IDEA можно открыть каталог проекта, выбрать JDK 17+, отметить
`src/main/java` как Sources Root и запустить метод `Main.main`.
Исходники и консольные сообщения используют UTF-8.

## Что реализовано

| Требование практики | Реализация |
| --- | --- |
| Проект по закреплённой теме | Консольный каркас платёжного шлюза |
| Основная сущность | `Payment`: идентификатор, сумма, валюта, описание, магазин |
| Связанная сущность | `Merchant`: идентификатор, название и сайт магазина |
| Связь объектов | Поле `Payment.merchant` хранит ссылку на объект `Merchant` |
| Конструкторы | Создают сущности с начальными значениями; пример находится в `Main` |
| Инкапсуляция | Все поля закрыты с помощью `private`, чтение через геттеры, изменение через сеттеры |
| Разделение модели и логики | Пакеты `model`, `service` и `console` |
| Консольный сценарий | Просмотр платежа и магазина, изменение описания платежа, выход |

В проекте `Merchant` означает продавца или магазин, принимающий оплату.
В исходной схеме в Obsidian он подписан как «Покупатель»; здесь используется
значение «магазин». Покупатель является отдельным участником предметной области.

Сумма представлена `BigDecimal`, чтобы хранить точное десятичное значение.
Пример создаётся из строки `"1490.00"`, без промежуточного `double`.
Идентификаторы, сумма, валюта и ссылка платежа на магазин задаются конструктором
и помечены `final`. У платежа можно менять описание, у магазина название и сайт.
`final` у ссылки на магазин запрещает заменить ссылку, но не делает сам магазин
неизменяемым.

## Структура

```text
src/main/java/ru/university/paymentgateway/
    Main.java
    model/
        Merchant.java
        Payment.java
    service/
        PaymentService.java
    console/
        ConsoleMenu.java
```

- `Main` содержит точку входа `public static void main(String[] args)`, создаёт
  магазин, связанный с ним платёж, сервис и меню.
- `model` описывает состояние сущностей и методы доступа к нему.
- `service` содержит операции с платежом. Пока это изменение описания через
  `PaymentService.updateDescription()`.
- `console` отвечает за ввод пользователя и вывод данных. Вспомогательные методы
  меню закрыты с помощью `private`.

`package` задаёт пространство имён класса. Например, полное имя класса платежа:
`ru.university.paymentgateway.model.Payment`. Структура каталогов повторяет
имя пакета, а `import` позволяет обращаться к классу из другого пакета по
короткому имени.

## Демонстрация на защите

1. Запустите `make run`.
2. Выберите `1`: появится платёж `1001` на сумму `1490.00 RUB`, его описание и
   название связанного магазина.
3. Выберите `2`: появятся идентификатор, название и сайт того же магазина.
4. Выберите `3` и введите `Оплата учебного заказа`.
5. Снова выберите `1`: описание платежа изменилось. Меню вызвало метод сервиса,
   а сервис изменил закрытое поле через `setDescription()`.
6. Введите `9` или текст: приложение сообщит о неизвестном пункте и продолжит работу.
7. Выберите `0`: приложение завершится.

Объекты создаются выражением `new`, которое вызывает конструктор.
Например, `new Merchant(1L, "Учебный магазин", "https://shop.example")`
создаёт магазин; затем этот объект передаётся в конструктор `Payment`.
`this` внутри конструктора или сеттера обозначает текущий объект и помогает
отличить его поле от одноимённого параметра.

`main` является `public`, чтобы быть доступным для запуска; `static` позволяет
вызвать его без создания объекта `Main`; `void` означает отсутствие возвращаемого
значения, а `String[] args` содержит аргументы командной строки.

### Модификаторы доступа

| Модификатор | Область доступа | Применение |
| --- | --- | --- |
| `public` | Из других классов и пакетов | Классы, конструкторы и доступные операции проекта |
| `protected` | В своём пакете и в подклассах; вне пакета действуют ограничения доступа через ссылку | Для расширения классов при наследовании |
| Без модификатора, package-private | Только внутри своего пакета | Для внутренних классов и методов пакета |
| `private` | Внутри своего класса | Поля сущностей и вспомогательные методы меню |

Пакеты `model`, `service` и `console` являются разными пакетами. Общий префикс
`ru.university.paymentgateway` не даёт им доступ к package-private членам друг друга.
`protected` и package-private на этом этапе объясняются как часть теории;
для текущей реализации достаточно `public` и `private`.

Прямое присваивание `payment.description = "..."` из меню не скомпилируется,
потому что поле `private`. Доступ осуществляется через методы объекта.
Наличие сеттеров само по себе не проверяет значения: правила валидации будут
добавлены в следующей практике.

## Границы этапа

Приложение хранит один демонстрационный платёж в памяти. Изменённое описание
сохраняется до завершения процесса; при новом запуске снова создаются исходные
данные. Реальные платежи не выполняются.

- Практика 2: бизнес-правила, проверка данных, исключения, коллекции, поиск,
  фильтрация и сортировка.
- Практика 3: PostgreSQL, JDBC и CRUD.
- Практика 4: интеграция и подготовка к защите КР №1.
